1. Structured Output
{week_2 01 Notebook}
- Take LLM output and make it compatible with downstream input
- Implementation options for Structured Output
        - 1: Use LLM call to take this output as input and give use the required structured output
        - 2: Regular python libraries/software, where we will need to struture output neatly (import instructor)
- All the structured outputs should be defined as pydantic schema
- Now the 'instructor' can be used with the created pydantic model
- 'instructor' injects the pydantic model and description in the prompt and you dont need to explicitly tell it about it

{week_2 02 Notebook}
- We now add the instructor to our backend application
- We return more meta data from our backend to have image and price as well in the rag_pipeline
- We integrate this with the frontend to show the image, price and description in the side bar

{week_2 03 Notebook}
- We will now integrate hybrid Search contextual + exact
- We need this because contextual works best in the similarity search of meaning and semantics but keyword heavy search then contextual search are not good
- For this we will store 2 vectors for a point in the qdrant
  |- 1. A dense vector for contextual embedding using voyage-3
  |- 2. A sparse vector for exact embedding using bm25
- While querying the qdrant, we will now use a fusion query which merges result from context retrieval and plain text search retrieval

{week_2 04 Notebook}
- Now we will use Reranking using cohere
- We select a reranking model and make a call to cohere api, give query and the retrieved context as input
- The api will then rerank these and give us the more better order

{week_2 05 Notebook}
- now we want to version the prompts so that we can manage better
- we can do that in 2 ways
        - Using prompt registry like langsmith
        - using jinja tempalting language to manage templates
        - versioning using YAML
- When iterate quickly along with fellow devs then YAML + git (Recommended)
- But when working with stake holders, then using prompt registry is better idea
- Therefore we first use 'jinja' to create templates
- We store the prompts in YAML so that it can be versioned because we dont want prompts to 
        present at random places in the code
        not even a separate python file because that can also create issues and get lost in large code base
- We create a folder prompts and create a retrieval_generation.yaml
- populate the prompt in yaml and create the funtion to get the prompt and make a template out of it
- Use the created template to create the actual prompt by injecting the fields

- We can also create a prompt in langsmith and use the langsmith client to fetch the prompt template
- use this template in code directly
- this is useful when working with someone not involved in code
